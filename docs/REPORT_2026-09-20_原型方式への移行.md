# REPORT（第14便）: 原型方式への移行

報告: 2026-09-20 ／ 開発側 → 監督
対象指示: 第14便（v6 を採用）
ステータス: **実装完了・検証済み。コミットのみ（push未実施）／コンタクトシートの目視監修待ち**

---

## 1. 何を変えたか

### 判定（`determinePersonalityType`）

if を積んだ判定木を、**最も近い原型のタイプを返す**形に置き換えました。

- 距離はユークリッド・等重み
- **フォールバックの分岐は存在しません。** 「どれにも当てはまらない場合」という
  コードそのものがありません。割合を下げたのではなく、概念を消しています
- 距離が完全に等しいときは `personalityTypes` の並びで先に来るほうを採ります。
  比較を「**より近いときだけ**更新」にすることで実現していて、例外処理ではありません
- 死んでいた分岐（`6-1`）も一緒に消えました
- 差分は **42行追加・71行削除**。判定木より短くなっています

### 原型（`src/lib/personality/prototypes.ts`・新規）

v6 の24タイプ×5軸を置きました。**このファイルが唯一の出典**です。
値の出どころ（定義から独立に置いた／逆算ではない）と、動かすときの注意
（0.125の格子を避ける／群の骨格を壊さない／間隔の都合だけで動かさない）を書いてあります。

### 代表値（`representative-scores.ts`）

判定エンジンの入力空間を走査して平均を取る**逆算をやめ、原型をそのまま返します**。
ファイルは59行から30行になりました。判定と表示で同じ数字を使うので、
片方だけ更新される余地がありません。

## 2. 番人テスト（`tests/prototypes.test.ts`・10本）

| # | 見ているもの | 結果 |
|---|---|---|
| 1 | 判定に「どれにも当てはまらない場合」の分岐が無い | ✅ |
| 2 | スコアが極端でも必ずどれかになる（3^5=243通り） | ✅ |
| 3 | 24タイプすべてに到達できる（原型を入れたらそのタイプ） | ✅ |
| 4 | 代表値が原型そのもの（二重管理の再発防止） | ✅ |
| 5 | 原型が24タイプ分そろい、1〜5の中にある | ✅ |
| 6 | 原型が0.125の格子を避けている | ✅ |
| 7 | 群の骨格（引火群と連鎖群が O と A で分離） | ✅ |
| 8 | 到達率0のタイプが無い | ✅ |
| 9 | 1タイプが15%を超えない | ✅ |
| 10 | すべてのタイプが2.0%以上 | 🔴 **既知の未達（skip）** |

**1つ目は条件分岐そのものの不在を見ています。** `if` が1つでもあれば
「当てはまらない場合」が生まれうるので、判定関数の中に距離比較以外の `if` が
増えたら落ちます。

### 10 について

**閾値を下げて通していません。** 実際に skip を外すと
`ウニコ型 1.27% / フェス型 1.48% / カンジ型 1.92% / レーダ型 1.62%` で落ちることを
確認してから、理由を書いて skip に戻しました。**形だけの skip ではありません。**

下げないのは、下げれば「達成した」ように見えるだけで実態が変わらないためです。
原型の調整は6版で打ち切っており、ここから先の均等化は**原型を定義から引き剥がす作業**に
なります（v5で間隔のためだけに動かした3手は正味 +0.19pt、うち1つは悪化しました）。
解消するときはこの skip を外します。

## 6. 別件として記録
