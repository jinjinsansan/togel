## 2. 🔴 いちばん大きい発見: **最も使っている太さのフォントが載っていません**

| 太さ | ソース内の使用数 | 読み込み |
|---|---|---|
| **900（`font-black`）** | **342箇所（最多）** | 🔴 **していない** |
| 700（`font-bold`） | 211箇所 | ✅ している |
| **600（`font-semibold`）** | **109箇所** | 🔴 **していない** |
| 500（`font-medium`） | **18箇所** | ✅ している |
| 400（`font-normal`） | 2箇所 | ✅ している |

`layout.tsx` が読み込んでいるのは **400 / 500 / 700** の3つだけです。

- **900 と 600 は、ブラウザが700から太さを合成して描いています（synthetic bold）。**
  日本語は画数が多いので、合成の太字は線が潰れて見えます。
  **見出し・タイプ名・ラベルはほぼ全部 `font-black`** なので、影響範囲は広いです
- 逆に **500 は18箇所しか使っていないのに読み込んでいます**（CSS 32KB分）
- `node_modules/@fontsource/noto-sans-jp/` には **900.css も 600.css も入っています**。
  読み込んでいないだけです

### 🔴 OG画像とサイトで、同じ太さの扱いが違います

OG画像は `src/assets/fonts/noto-sans-jp-japanese-900-normal.woff` を**同梱して使っています**。
つまり **シェア画像は本物の900、サイトは合成の900** です。
同じ「〜型」の文字が、画像とページで別の太さで描かれています。

## 3. CSS 113KB のうち 96KB は「フォントの宣言だけ」

| ファイル | 中身 | 圧縮後 |
|---|---|---|
| CSS ①②③ | `@font-face` が **124本ずつ**（400 / 500 / 700） | 32KB × 3 = **96KB** |
| CSS ④ | Tailwind の出力 | 15KB |

日本語フォントは文字集合を124個に分割してあり、**ブラウザは必要な分だけ落とします**。
だから**フォント本体の転送は軽い**のですが、**宣言そのもの（96KB）は全ページで毎回読まれます。**

- CSSの **85% がフォント宣言**です
- 500を外せば 32KB 減り、900を足せば 32KB 増えます（差し引きゼロで太さが正しくなります）
- `font-display: swap` は指定済みなので、フォント待ちで文字が消えることはありません
