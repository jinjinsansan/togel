# 「独自の診断方法」の実体（事実確認）

作成: 2026-09-20 ／ 状態: **事実確認のみ。評価・判断はしていません**

「土台が5因子モデルであること」と「独自の診断方法であること」の関係を、
コードから読める事実だけで整理します。**こう名乗るべき、という提案は含みません。**

---

## 1. 採点の流れ（4段）

```
① 回答（1〜5のリッカート）
     ↓  軸ごとに単純平均
② 5軸の素点（1.00〜5.00）
     ↓  閾値 >=4 を high、<=2 を low に振り分け
③ high / low の組み合わせを判定木に通す
     ↓
④ 24タイプのどれか
```

- ①→②: `engine.ts` の `calculateBigFiveScores`。**重みなしの単純平均**です
- ②→③→④: `personality/utils.ts` の `determinePersonalityType`。
  `if` を積んだ**判定木**で、`getPersonalityTypeById` の呼び出しが30か所あります

## 2. 5因子をどう使っているか

| 段 | 5因子由来か | 中身 |
|---|---|---|
| 設問40問 | **そのまま** | 開放性・誠実性・外向性・協調性・神経症傾向を各8問 |
| 軸の素点 | **そのまま** | 5軸の平均値。標準化も重み付けもしていません |
| 閾値（>=4 / <=2） | 独自 | 固定値。研究上の基準ではありません |
| 24タイプへの対応付け | **独自** | high/low の組み合わせを判定木で24分岐 |
| ミスマッチ判定 | **独自** | 後述 |
| 表示の語彙 | **独自** | 「引火点」「構造強度」等（`togel-index.ts`） |

**5因子から借りているのは①と②まで**です。③以降は全部この実装で定義しています。

---

## 3. 独自なのはどこか（3つ）

### 3-1. 24タイプへの対応付け

5因子には「タイプ」という概念がありません（連続量の5軸）。
それを high/low に離散化し、組み合わせを**24個の名前付きタイプ**に割り当てているのが
この実装の定義です。判定木の分岐条件（どの組み合わせがどのタイプか）は、
研究から導けるものではなく、**Togelが決めたもの**です。

### 3-2. ミスマッチ判定（この商品の主役）

各タイプ定義が `badCompatibleTypes`（合わない相手）を**明示的に持って**います。

```ts
// definitions.ts
badCompatibleTypes: ["reliable-organizer", "conscientious-guardian", "methodical-thinker"],
```

- 5因子には「誰と合わないか」を出す仕組みはありません
- スコアの差分だけで機械的に出しているのでもなく、**タイプごとに人が書いた組み合わせ**です
- 「運命の人は教えない。地雷なら教える。」というコンセプトの実体はここにあります

### 3-3. 取扱指標の語彙と、群の再定義

- 5軸に「引火点 / 構造強度 / 放熱量 / 緩衝性能 / 耐圧限界」という名前を与えています
- 神経症傾向は向きが逆になるので、表示時に反転しています（`inverted`）
- 24タイプを4群に束ね、**群名には必ず再定義の一行が付く**構造になっています
  （`group-badge.tsx` が名前だけの取り出しを許さない形で保持）

## 5. 事実のまとめ

- **土台**: 5因子モデルの設問と、軸ごとの単純平均。ここは借りています
- **独自**: 離散化の閾値、24タイプへの対応付け、ミスマッチの組み合わせ、
  取扱指標の語彙、4群と再定義。**②より後ろは全部この実装の定義**です
- **内部の記述だけが古い**。ユーザーからは見えませんが、コードを読む人には見えます
- 🔴 **なお、`ANALYSIS_2026-09-20_設問と採点.md` の通り、いまは①②の段に
  測定上の問題があります**（全問が正方向のため、回答スタイルでタイプが決まりうる）。
  「独自なのは③以降」という整理は、①②が正しく測れていることを前提にしています
