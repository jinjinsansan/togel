# メール認証とメルマガ 切り替え手順書

作成: 2026-11-04 ／ 対象: オーナー（各コンソールの操作）

## 何が変わったか（コードの側は済んでいます）

| 以前 | いま |
|---|---|
| Googleログインだけ | **メールアドレス＋パスワード**（新規登録・ログイン・パスワード再設定） |
| LINE公式アカウントの友だち追加・週1のLINE配信・LINE内の診断（LIFF） | **すべて撤去**。代わりに**メルマガ**（週1通・全15通。文面はLINE配信のものを引き継ぎ） |
| お問い合わせは LINE | **support@to-gel.com**（メール）に一本化 |
| 「登録なしで開始」 | 「メールで無料登録」。**診断の前に登録**するのは従来どおり |

メールの送信は **Resend の無料枠**（1日100通・月3,000通）を使います。
Cloudflare は **DNS（ドメイン認証のレコード）** と **support@ の受信（Email Routing・無料）** に使います。
Cloudflare のメール**送信**は無料枠では任意の宛先に送れないため（Workers Paid が要る）、使っていません。

**下の手順が終わるまで、本番ではログインも新規登録もできません**（Googleのボタンを消したため）。
順番どおりに進めてください。デプロイ（main への push）は **1〜4 が終わってから**にしてください。

---

## 1. Resend（送信）

1. https://resend.com でアカウントを作る（無料）
2. **Domains → Add Domain → `to-gel.com`**
3. 表示された DNS レコード（SPF の TXT、DKIM の TXT/CNAME、任意で DMARC）を、
   **Cloudflare の DNS** に追加する。**プロキシ（オレンジの雲）はオフ**（DNS only）
4. Resend の画面で **Verified** になるまで待つ
5. **API Keys → Create API Key**（権限は Sending access、ドメインは to-gel.com）。値は控えておく

## 2. Cloudflare（受信）

1. to-gel.com → **Email → Email Routing** を有効にする
2. **support@to-gel.com** を、普段読んでいるアドレスへ転送する設定を作る
   （メルマガの返信先・解除の mailto もここに届きます）

## 3. Supabase（認証）

ダッシュボード → 対象プロジェクト。

1. **Authentication → Sign In / Providers**
   - **Email**: 有効。**Confirm email: オン**（確認していないアドレスにはメルマガを送らない作りです）
   - **Minimum password length: 8**（画面の案内と揃える）
   - **Google: オフ**（以前の利用者は「パスワードを忘れた」から同じアカウントに入れます。下の §6）
2. **Authentication → Emails → SMTP Settings**（Supabase 内蔵のメールは送信数がごく少ないため必須）
   - Enable custom SMTP: オン
   - Host `smtp.resend.com` ／ Port `465` ／ Username `resend` ／ Password = 1-5 の API キー
   - Sender email `noreply@to-gel.com` ／ Sender name `Togel`
3. **Authentication → Emails → Templates**。リンクの行を次に置き換える
   （**別のブラウザやメールアプリの中で開いても通る形**です。既定のままだと、登録した端末の同じブラウザでしか通りません）
   - Confirm signup:
     `{{ .SiteURL }}/auth/callback?token_hash={{ .TokenHash }}&type=signup`
   - Reset password:
     `{{ .SiteURL }}/auth/callback?token_hash={{ .TokenHash }}&type=recovery`
   - 件名・本文は日本語に（例: 件名「【Togel】メールアドレスの確認」「【Togel】パスワードの再設定」）
4. **Authentication → URL Configuration**
   - Site URL: `https://to-gel.com`（本番のURL）
   - Redirect URLs に `https://to-gel.com/**` を追加（プレビュー環境も使うならそのURLも）

## 4. データベース

SQL Editor で `supabase/migrations/20261104_newsletter.sql` を実行する
（`newsletter_subscribers` テーブルを作るだけ。既存のテーブルは触りません）。

## 5. Vercel（環境変数）

Production に設定して、**再デプロイ**する（環境変数の変更は既存のデプロイに反映されません）。

| 変数 | 値 |
|---|---|
| `RESEND_API_KEY` | 1-5 のキー |
| `RESEND_FROM_EMAIL` | `Togel <noreply@to-gel.com>` |
| `CRON_SECRET` | **自分で生成**（例: `openssl rand -hex 32`）。外部から提示された値は使わない |
| `NEXT_PUBLIC_APP_URL` | `https://to-gel.com` |
| `NEWSLETTER_DAILY_LIMIT` | 省略可（既定80。確認メール等に20通を残す） |

不要になったもの（削除してよい）: `LINE_CHANNEL_SECRET`・`LINE_CHANNEL_ACCESS_TOKEN`・
`NEXT_PUBLIC_LIFF_ID`・`LINE_BROADCAST_START_AT`。

`CRON_SECRET` と `RESEND_API_KEY` の両方が揃うまで、メルマガの cron は
`503 {"error":"newsletter disabled","missing":[...]}` を返して何も送りません。
画面の「週に1通、全15回」もその間は出ません（登録だけは受け付け、揃った時点で1通目から届きます）。

## 6. 以前 Google で登録した人

同じメールアドレスで **ログイン画面 →「パスワードを忘れた／以前Googleで登録した」** から
再設定メールを受け取り、パスワードを決めれば、**同じアカウント（診断履歴ごと）**に入れます。
新規登録を試した場合も「登録済みです」と出て、同じ案内をします。
既存の利用者へ一度お知らせを送るなら、この手順を書いてください。

## 7. LINE公式アカウント

サイトからの導線と配信の仕組みは消しました。アカウント自体の扱い（あいさつ文・自動応答で
「メルマガに移りました」と案内する、停止する等）は LINE Official Account Manager で決めてください。
DB の `line_users` テーブルは**消していません**（過去の記録として残しています）。

## 確認（デプロイ後）

1. シークレットウィンドウでトップ →「地雷を見る」→ 新規登録 → 届いたメールのリンク → 診断の選択画面に着く
2. スマホのメールアプリから確認リンクを開いても登録が完了する（§3-3 のテンプレートが効いているか）
3. ログアウト → ログイン、「パスワードを忘れた」→ 再設定 → 新しいパスワードで入れる
4. 結果画面の「メルマガを受け取る」→ マイページの「メルマガ」がオンになっている
5. 配信の確認（実際には送らない）:
   `curl -H "Authorization: Bearer $CRON_SECRET" "https://to-gel.com/api/cron/newsletter?dryRun=1"`
6. 自分宛てにだけ実送信: `...?to=自分のアドレス`（購読済みであること。最大5件）→ 届いたメールの「配信の解除」が効く

## 知っておくこと

- **Resend 無料枠は1日100通**。購読者が1日に送る数を超えたら、溢れた人は翌日に回ります
  （通目は人ごとに数えるので、飛んだり重複したりはしません）。週あたり約560人までが目安です。
  超えるようなら Resend の有料プラン（月20ドル〜）に上げて `NEWSLETTER_DAILY_LIMIT` を上げる
- 既存の管理画面の「お知らせ一斉送信」（`/admin/notifications`）は**全ユーザーに送ります**。
  同じ Resend の枠を使うので、使うと当日のメルマガが減ります。また、宣伝の内容を送るなら
  特定電子メール法の同意が要ります（メルマガの購読者だけに送るべき内容かどうかを確認してください）
- プライバシーポリシーに「メルマガの配信」と「メール配信事業者（海外を含む）への委託」を足しました。
  法務確認（BLOCKED 6番）の対象に含めてください
