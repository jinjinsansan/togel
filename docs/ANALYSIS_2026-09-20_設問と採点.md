## 0. 先に、依頼内容の訂正が1件

「逆転項目は `争いを避ける方だ` の1問だけ」とのことでしたが、**逆転項目は0問です。**

`争いを避ける方だ` は協調性（agreeableness）に対して**正方向**の項目です。
「争いを避ける＝協調的」なので、他の7問と同じ向きを向いています。
**40問すべてが正方向で、逆転項目は1つもありません。**

## 1. これは理論上の話ではありません（実測）

全問に同じ値で答えたとき、どのタイプになるかを実際に計算しました。

| 全問の回答 | 出るタイプ |
|---|---|
| 全部 5（よく当てはまる） | **タイシ型**（relational-ambassador） |
| 全部 4 | **タイシ型**（同上） |
| 全部 3 | マッチャ型（contemplative-sage） |
| 全部 2 | レーダ型（quiet-observer） |
| 全部 1 | レーダ型（同上） |

**「はい」と答えがちな人は、性格に関係なく全員タイシ型になります。**
「いいえ」寄りの人は全員レーダ型です。24タイプのうち2つに吸い込まれる経路が、
回答スタイルだけで開いています。

## 2. 🔴 採点コードは逆転項目を扱えません（それ以前の問題があります）

`engine.ts` の採点は、**設問オブジェクトを一度も見ていません。**

```ts
// src/lib/matching/engine.ts:398
function getTraitFromQuestionId(questionId: string): TraitKey | null {
  const key = traitKeyMap[questionId[0]?.toLowerCase() ?? ""];  // ← idの1文字目だけ
  return key ?? null;
}
```

軸を**設問IDの先頭1文字**（`o` `c` `e` `a` `n`）から引いています。
`questions.ts` は参照されません。したがって:

- 設問に `reverse: true` を足しても、**採点側からは見えません**（無視されます）
- 逆転を入れるには、`calculateBigFiveScores` が設問を引けるようにする改修が要ります
- 新しい設問のIDは、今後も軸の頭文字で始める必要があります（この規約が暗黙です）

なお `togel-index.ts` の `inverted` は、ご想定のとおり**表示の反転**です
（神経症傾向→「耐圧限界」の向き合わせ）。設問の逆転とは別物で、流用できません。

## 3. 提案：構造と採点の設計

**文面は書きません。** 構造だけ出します。

### 3-1. データ側

`DiagnosisQuestion` に任意の真偽値を1つ足します。

```ts
/** true: 高く答えるほど、その軸が低いことを示す項目 */
reverse?: boolean;
```

**light と full の対応は壊れません。** `fullQuestions` は `baseQuestions` を
スプレッドして作っているので（`...baseQuestions.map(...)`）、
**baseQuestions に付けた印は full にも自動で伝わります。**

ただし裏返すと制約になります。**light の設問に逆転を足すと、full 側の同じ設問も
必ず逆転します。** light だけ／full だけ逆転にすることはできません
（そうしたい場合は別IDの設問に分ける必要があります）。

### 3-2. 採点側

```ts
// 逆転項目は 1↔5 / 2↔4 に読み替える（6 - value）
const effective = question.reverse ? 6 - answer.value : answer.value;
```

`calculateBigFiveScores(answers)` に**診断タイプを渡す**必要があります
（`getQuestionsByType(plan)` で設問表を引くため）。呼び出し元は3か所
（`generateDiagnosisResult` / `generateMatchingResults` / `generateMismatchingResults`）で、
いずれも `payload.diagnosisType` を持っているので、引数を増やすだけで足ります。

### 3-3. 何問を逆転にするか

| 版 | 1軸あたり | 逆転にする数 | 合計 |
|---|---|---|---|
| full（40問） | 8問 | **3問** | 15問 |
| light（10問） | 2問 | **1問** | 5問 |

- **full で3/8**: 半々に近づけるほど回答スタイルは打ち消せますが、
  逆転項目は読み間違いが起きやすく（「〜しないほうだ」に「はい」）、
  増やしすぎると別のノイズが乗ります。3〜4が通常の落としどころです
- **light で1/2**: 1軸2問しかないので、**1問が限界**です。
  ただし2問中1問を逆転にすると、**その軸は「2問の平均」ではなく
  「賛成1問と反対1問の突き合わせ」になります。** 本当に極端な人ほど
  中央に引き戻されるので、light の解像度はさらに落ちます
- 🔴 **light を10問のままにするなら、逆転を入れても回答スタイルは半分しか消えません。**
  light の位置づけ（味見用）を変えないなら、これは許容する判断だと思います

## 4. 🔴 逆転だけ入れると、別の壊れ方をします（重要）

タイプ判定の閾値は固定値です。

```ts
// src/lib/personality/utils.ts
if (scores.openness >= 4) high.push("O");
if (scores.openness <= 2) low.push("O");
```

いまは全問正方向なので平均が上に寄り、`>= 4` が立ちやすくなっています。
**逆転項目を入れると平均が中央（3前後）に寄るので、`>= 4` も `<= 2` も
立ちにくくなります。** その結果、high も low も空の人が増え、
判定木の**フォールバック側に大量に流れ込みます**（全部3 → マッチャ型）。

つまり「回答スタイルで2タイプに吸い込まれる」問題を直すと、
**閾値をそのままにした場合、今度は別の1タイプに吸い込まれます。**

- **逆転項目と閾値は、必ず同じ回で見直してください。** 片方だけは危険です
- 閾値を素点の固定値ではなく**分布の位置**（例: 上位/下位いくらか）で決める案もありますが、
  利用者8人では分布が取れません。**当面は固定値のまま、逆転後の想定分布に合わせて
  数字を引き下げる**のが現実的だと考えます（具体値は実装時に計算します）

## 6. 依頼外で見つかったもの（2件・報告のみ）

### 6-1. 🔴 選択肢2の文言が、意味と点数で逆を向いています

```ts
// src/data/questions.ts
{ value: 1, label: "全く違う" },
{ value: 2, label: "あまり違わない" },   // ← ここ
{ value: 3, label: "どちらでもない" },
{ value: 4, label: "少し当てはまる" },
{ value: 5, label: "よく当てはまる" },
```

`あまり違わない` は「**あまり違わない＝だいたい合っている**」と読めます。
点数は2（否定寄り）ですが、**言葉は肯定寄り**です。
1→5 が「違う→当てはまる」なら、2は `あまり当てはまらない` でないと向きが揃いません。

**全設問・全回答者に効きます。** 逆転項目より先に直す価値があるかもしれません。
**文面なので直していません。**

### 6-2. 🟡 指標のバーが、実際より常に高く出ます

```ts
// src/lib/personality/togel-index.ts
const pct = Math.round((scores[key] / 5) * 100);
```

1〜5のスコアを `/5` で0-100に変換しているため:

| 素点 | 表示 |
|---|---|
| 1（最低） | **20%** |
| 3（中央） | **60%** |
| 5（最高） | 100% |

**最低でも20%、中央が60%**になります。バーが空になることはなく、
「どちらでもない」が過半数に見えます。1〜5を0-100に素直に移すなら
`(score - 1) / 4 * 100` で、中央が50%・最低が0%になります。

これは**1の問題を見えにくくしています**——「はい」寄りの人のバーが
さらに高く描かれるためです。ただし**見た目が大きく変わる**ので、
判断が要ると考えて触っていません。
